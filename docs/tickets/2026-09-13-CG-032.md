# CG-032 — LLM observability and cost accounting

Date: 2026-09-13
Status: Planned
Depends on: CG-020, CG-027

## Outcome

Emit a structured span for every provider call: prompt name/version, model,
input/output token counts, latency, estimated cost and outcome
(ok/timeout/rate-limited/refusal/error). Spans integrate with CG-027 telemetry
and are privacy-safe by default (no raw prompt/response text).

This is a post-v1 job-skill extension (LLM observability, token/cost tracking),
not a v1 release requirement.

## Contract

1. A span is emitted for every attempted provider call, including failures.
2. Spans capture model, prompt name/version, input/output tokens, latency ms,
   estimated cost and a typed outcome; never raw prompt or response text by default.
3. Cost estimate is a pure function of tokens and a per-model rate table with no network.
4. Recording is optional (no-op recorder) and must never fail the call it wraps.
5. Aggregated counters (calls, tokens, cost, error rate) are exposable via CG-027.

## Acceptance criteria

- A mocked provider call produces a span with correct token and latency fields.
- Cost estimate matches the rate table for known token counts.
- Redaction test proves no prompt/response text appears in the span.
- A recorder that raises does not break the underlying LLM call.

## Non-goals

- A hosted tracing SaaS integration (LangSmith/OTel exporters) beyond CG-027 seams.
- Sampling strategies or distributed trace propagation.
- Prompt content logging; that stays out of scope for privacy.

## TDD loop

1. Write a failing test asserting span fields for a mocked call.
2. Run it and confirm it fails for the expected reason.
3. Add the span model and no-op recorder.
4. Wire recording around the adapter; add the redaction and cost tests.
5. Add a recorder-raises test proving the call still succeeds.
