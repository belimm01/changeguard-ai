# CG-020 — Integrate optional AI explanatory enrichment

Date: 2026-09-10
Status: Planned
Depends on: CG-014, CG-017, CG-018, CG-019

## Outcome

Add optional AI-generated explanation fields to API reports: human-readable risk explanation, recommended tests, migration notes and rollback considerations. AI enrichment is explicitly advisory, citation-validated and never allowed to remove, downgrade or replace deterministic findings.

If the model is unavailable, times out or fails validation, the API returns deterministic results with an explicit partial AI status. It must not silently omit AI risk.

## Contract

1. Deterministic findings are computed first and are the source of truth.
2. AI receives only CG-017 selected context, deterministic findings and bounded report metadata.
3. AI may add labeled fields: `advisory_explanation`, `recommended_tests`, `migration_considerations`, `rollback_considerations` and validation status.
4. AI cannot remove a deterministic finding, change its rule ID, change evidence, lower severity or mark a risk resolved.
5. AI output must pass CG-019 validation before appearing as supported advisory text.
6. Unavailable model, timeout, budget rejection, malformed output or citation-validation failure returns deterministic report plus explicit status such as `ai_status: unavailable|partial|invalid`.
7. API HTTP success for deterministic analysis remains possible when AI fails. Only malformed request/auth failures should use error responses owned by CG-014.
8. Prompt and response handling must not expose tools, secrets, repository execution or hidden chain-of-thought requests.

## Acceptance criteria

- With a fake valid adapter, the API/report includes labeled advisory explanation and recommended tests with accepted citations.
- With a disabled adapter, the API/report includes deterministic findings and explicit AI unavailable status.
- With fabricated AI evidence, deterministic findings remain unchanged and rejected AI items are counted.
- A model suggestion cannot downgrade or remove a deterministic high-risk finding.
- If AI suggests no risks while deterministic findings exist, deterministic findings still appear and AI status explains the mismatch or rejection.
- Recommended tests and rollback considerations are attached only as advisory fields, not as required merge gates.
- Endpoint tests use fake adapters; they do not call external providers.

## Security and failure semantics

- Repository text and model output are both untrusted.
- Do not let model text promise safety, compliance or exploitability as a confirmed fact unless deterministic evidence supports that exact claim.
- AI partial status must be visible to clients. Silent no-op AI is a failure.
- Do not log prompts containing repository content unless an explicit debug mode with redaction exists.

## Non-goals

- Autonomous code edits, branch pushes, merge decisions or blocking checks.
- Provider activation or vendor-specific tuning.
- Background job persistence; CG-015 owns durable report storage and jobs.
- New deterministic rules for OpenAPI, Avro or Kubernetes.
