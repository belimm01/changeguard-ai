# CG-010 — Fetch safe base/head file content and diff-line evidence

Date: 2026-09-10
Status: Planned
Depends on: CG-009

## Outcome

ChangeGuard can fetch base/head file contents and bind diff-line evidence to the exact PR SHAs without checking out or executing repository code, while rejecting traversal, symlinks, oversized content, and stale SHA mismatches.

## Design principles

- Fetching content by API and SHA is safer than local checkout for untrusted PRs.
- Evidence must identify which revision it came from: base, head, and commit SHA.
- Paths and links from a remote repository remain untrusted even after GitHub returns them.

## Files

Create proposed:

- `src/changeguard/adapters/github_content.py` — safe content and diff evidence reader.
- `src/changeguard/domain/content.py` — immutable file content, content status, and line-reference models.
- `tests/unit/adapters/test_github_content.py` — mocked API tests for safe fetching and evidence binding.

Modify existing:

- `src/changeguard/adapters/github_client.py` — add low-level API method only if it keeps the adapter cohesive.
- `src/changeguard/domain/reports.py` — connect line evidence and partial coverage to reports.
- `src/changeguard/domain/models.py` — reuse existing path validation or extract shared validation if needed.

## Acceptance criteria

- Content fetches identify repository, relative path, revision kind (`base` or `head`), and the exact SHA used for the request.
- The implementation does not call `git checkout`, execute hooks, import repository code, run package managers, or follow local filesystem paths.
- Absolute paths, `..`, backslashes, null bytes, and empty paths are rejected before requesting content.
- Symlink responses or GitHub object modes indicating symlink/submodule are reported as unsupported or partial, not followed.
- Per-file and aggregate byte limits are enforced; exceeded limits produce partial coverage with the path and reason.
- Base/head SHA mismatches between PR metadata and fetched content are detected and reported as stale/incomplete instead of silently analyzed.
- Diff-line evidence can refer to file path, side (`base`/`head`), start line, end line, and source SHA.
- Deleted files and binary/undecodable content have explicit coverage states.
- Tests use mocked HTTP responses; no live GitHub or local repository reads.

## Non-goals

- No deterministic OpenAPI/Avro/Kubernetes rules yet.
- No full unified-diff parser beyond the line evidence needed by immediate rules.
- No local clone, worktree, sandbox, or code execution feature.
