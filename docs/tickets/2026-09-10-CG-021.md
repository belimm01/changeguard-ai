# CG-021 — Build reproducible offline evaluation harness and dataset

Date: 2026-09-10
Status: Planned
Depends on: CG-011, CG-012, CG-013, CG-020

## Outcome

Create a reproducible evaluation harness for deterministic rules and AI advisory enrichment using offline fixtures by default. The harness reports declared numeric metrics, negative-example behavior and frozen AI-quality results separately from deterministic correctness.

Default evaluation must run without network, provider credentials or live model cost. Optional live AI evaluation is a separate, explicitly cost-bounded mode.

## Files

- `tests/evaluation/test_offline_evaluation.py` — pytest entry point for deterministic evaluation metrics.
- `tests/fixtures/evaluation/manifest.json` — dataset manifest with case IDs, expected rules and metric thresholds.
- `tests/fixtures/evaluation/openapi/` — CG-011 positive and negative examples.

## Contract

1. Offline evaluation is the default and uses repository fixtures only.
2. Deterministic fixture expectations must be exact: expected finding IDs, evidence source IDs and absence of findings for negative examples.
3. Declare numeric thresholds in the manifest, including `citation_validity == 1.0` for accepted AI advisory items and `deterministic_fixture_accuracy == 1.0` for the included deterministic fixtures.
4. AI quality examples are frozen before a run as structured fixture outputs; live model calls are excluded from default pytest.
5. Negative examples must include safe changes that look similar to risky changes but should not trigger findings.
6. The harness must reject fabricated evidence rather than counting it as a low-quality answer.
7. Reports include counts: cases evaluated, deterministic pass rate, citation validity, rejected fabricated evidence count and skipped live-AI status.
8. Optional live evaluation requires explicit CLI flag or environment opt-in plus max cases and cost/time budget.

## Acceptance criteria

- `uv run pytest tests/evaluation/test_offline_evaluation.py -q` runs without network credentials.
- Included deterministic fixtures produce `deterministic_fixture_accuracy == 1.0`.
- Accepted AI fixture citations produce `citation_validity == 1.0`.
- A fixture with fabricated evidence is rejected and counted, not accepted with a lower score.
- Negative examples for OpenAPI, Avro and Kubernetes do not produce the target risk findings.
- Evaluation output is reproducible across runs and does not depend on dictionary or filesystem nondeterminism.
- Documentation states live AI evaluation is optional, cost-bounded and not part of default CI.

## Security and failure semantics

- Do not execute repositories, manifests or fixture text.
- Do not call live providers unless explicit opt-in is present in the command being run.
- Do not let model-generated claims create gold labels during a run. Gold data is reviewed fixture data only.
- A missing optional live provider is reported as skipped live evaluation, not as passing AI quality.

## Non-goals

- Large benchmark suite or statistical model evaluation platform.
- Vendor-specific prompt comparison.
- CI enforcement beyond declared offline thresholds.
- Mutation testing or fuzzing; CG-022 owns adversarial regressions.

## TDD loop

1. Create a tiny manifest with one deterministic fixture and write a failing test that expects `deterministic_fixture_accuracy == 1.0`.
2. Run the focused evaluation test and confirm the harness/fixtures are missing.
3. Implement manifest loading with strict validation and stable ordering.
4. Add OpenAPI, Avro and Kubernetes positive/negative cases one family at a time.
5. Add frozen AI accepted and fabricated-evidence fixtures through CG-019 validation.
6. Add optional live-mode guard test proving no provider call occurs by default.
