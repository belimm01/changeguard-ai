# CG-036 — Add a read-only MCP server for ChangeGuard reports and evidence

Date: 2026-09-14
Status: Planned
Depends on: CG-015, CG-019, CG-027

## Outcome

ChangeGuard exposes a custom read-only MCP server that lets an approved MCP client inspect persisted analysis reports, evidence, coverage limitations and citation-validation results without granting repository write access, shell access, arbitrary code execution, or merge authority.

## Practical use

This milestone exists so a developer can ask an MCP-aware assistant questions such as "show the latest ChangeGuard report for owner/repo PR 123", "list findings with evidence ranges", or "explain why this report is partial" while preserving the same advisory boundary as the API and GitHub Check output. It is not a general agent framework requirement and it must not be used to accumulate technologies without a demonstrated client workflow.

## Design principles

- MCP tools are another external boundary: authenticate, validate inputs, authorize least privilege, and return bounded report data.
- Repository content, PR text, findings, citations and future model output remain untrusted data. Tool descriptions and responses must not be treated as instructions to the hosting assistant.
- The MCP server reads ChangeGuard state; it does not trigger analysis, edit branches, execute repository code, call model tools, approve checks, merge, or auto-remediate.

## Files

- `tests/unit/mcp/test_tools.py` — input validation, auth and sanitized output tests using repository fakes.
- `tests/integration/mcp/test_mcp_server.py` — live MCP smoke test against a disposable app/database.

Modify existing:

- `src/changeguard/config.py` — add MCP enablement, auth token and repository allow-list settings without logging secrets.
- `src/changeguard/repositories/analysis_jobs.py` or the accepted CG-015 report repository — add query methods only as needed for read-only tools.

## Tool contract

Provide only narrowly scoped read tools, for example:

- `get_report(owner, repo, pr_number, head_sha=None, analysis_version=None)` — returns one persisted versioned report plus report identity and coverage.
- `list_findings(owner, repo, pr_number, head_sha=None, severity=None)` — returns bounded finding summaries and report identity.
- `get_evidence(report_id, finding_id)` — returns validated evidence paths/ranges and citation status, not arbitrary files.
- `explain_coverage(report_id)` — returns partial/unsupported reasons and limits recorded by ChangeGuard.

All result shapes must be stable JSON-compatible data derived from persisted reports. Do not expose raw tokens, local file paths, environment variables, stack traces, unchecked markdown-as-instructions, or arbitrary repository file reads.

## Acceptance criteria

- MCP server is disabled by default and requires explicit configuration to run.
- Authentication is required for every tool call; invalid or missing credentials fail closed and leak no configured secret.
- Authorization enforces least privilege by repository allow-list/scope and denies cross-repository report access.
- Inputs validate owner, repository name, PR number, SHA, report id, finding id, pagination and size limits; invalid inputs return bounded errors.
- Tool handlers read only persisted PostgreSQL reports/evidence from CG-015/CG-019 paths and never execute repository code, shell commands, Git operations, model tool calls, branch writes, Check updates, auto-merge or auto-approval.
- Prompt-injection trust boundary is documented and tested: repository text, findings, citations and model output are untrusted payload data, never host-assistant instructions.
- Results include coverage/partial/unsupported status so missing evidence cannot look clean.
- Unit tests cover auth, least privilege, validation, bounded output, sanitized errors and prompt-injection fixture text.
- Integration tests run against a real disposable PostgreSQL database and live MCP server process/client transport; mock-only tests do not satisfy acceptance.
- A documented live smoke uses one actual MCP client configuration to call at least `get_report` and `get_evidence`, records redacted command/output, and verifies the client receives read-only data.
- No Agno or agent framework is added unless a separate accepted design note proves it is needed for this scoped MCP workflow.

## Non-goals

- No arbitrary code execution, shell access, repository checkout reads, GitHub writes, branch edits, auto-fixes, auto-merge, auto-approval, or policy enforcement.
- No public unauthenticated MCP endpoint, SaaS multi-tenancy, or broad cross-repository search.
- No replacement for the HTTP API, GitHub Check delivery, worker queue, or offline evaluation.
- No embeddings/vector database work; CG-031 owns optional semantic retrieval.
