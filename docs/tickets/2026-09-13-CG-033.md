# CG-033 — Resilient provider calls: retries, backoff and optional cache

Date: 2026-09-13
Status: Planned
Depends on: CG-018

## Outcome

Wrap the CG-018 LLM boundary with bounded retries, exponential backoff with
jitter for transient failures (timeout, 429, 5xx), and an optional deterministic
response cache keyed by a request hash. Budgets and cost ceilings from CG-018 are
still enforced before any attempt. Default runtime remains offline and network-free.

This is a post-v1 job-skill extension (production LLM resilience), not a v1
release requirement. It supersedes CG-018's "automatic retries" non-goal.

## Contract

1. The wrapper implements the CG-018 protocol so it is a drop-in adapter.
2. Retry only transient outcomes (timeout, 429, 5xx); never retry refusals,
   schema/validation errors or budget rejections.
3. Backoff is exponential with bounded max attempts and jitter; the sleep function
   is injectable so tests are deterministic and fast.
4. Total attempts respect the CG-018 timeout/cost budget; the wrapper never exceeds it.
5. Optional cache is keyed by a stable hash of the request; identical requests
   return the cached result without a provider call. Cache is opt-in.
6. Wrapping a disabled adapter still yields an explicit unavailable status with no network.

## Acceptance criteria

- A transient-then-success sequence retries the expected number of times and succeeds.
- A refusal or schema error is not retried.
- Backoff delays match the schedule using an injected sleeper (no real sleeping).
- Cache hit returns the prior result with zero additional provider calls.
- Budget/cost ceiling is never exceeded across retries.

## Non-goals

- Distributed or persistent cache; in-memory single-process only here.
- Circuit breakers or adaptive concurrency; out of scope for v1 extensions.
- Semantic (embedding-similarity) caching; exact-request cache only.
