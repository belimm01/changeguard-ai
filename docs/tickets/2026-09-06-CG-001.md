# CG-001 — Model and validate pull-request changes

Date: 2026-09-06
Status: Done

## Outcome

ChangeGuard represents a pull request's changed files as an immutable
collection and rejects invalid input at its first internal boundary.

## Design principles

- `ChangedFile` is a small typed value object: a frozen, slotted dataclass.
  `frozen=True` makes fields read-only; `slots=True` rejects undeclared
  attributes such as a misspelled `additons`.
- Invariants live in `__post_init__`, so they hold for every instance no matter
  whether it comes from GitHub, the CLI or a test.
- Repository paths and patch text are untrusted input. Invalid paths are
  rejected, never silently repaired.
- The domain model stays independent of external frameworks.

## Files

- `src/changeguard/domain/models.py` — `ChangeType`, `ChangedFile`, `ChangeSet`
- `tests/unit/test_models.py`

## Contract

`ChangedFile(path, change_type, additions, deletions, patch=None)`:

- rejects with `ValueError`: empty paths, absolute paths, any `..` segment,
  backslashes, null bytes, and negative `additions` or `deletions`;
- accepts `patch=None`, because providers omit patches for binary or oversized
  changes;
- is immutable after construction.

`ChangeSet(files)` exposes calculated `total_additions` and `total_deletions`
properties. There are no stored totals that could drift from `files`, and an
empty change set totals zero.

## Acceptance criteria

- A parameterized test covers every invalid path category and the negative
  counters.
- Valid input, including `patch=None`, is accepted.
- The immutability test passes.
- Totals are correct for empty and multi-file change sets.
