# CG-017 — Retrieve deterministic baseline context within budget

Date: 2026-09-10
Status: Planned
Depends on: CG-016

## Outcome

Select the most relevant CG-016 corpus chunks for each changed file and finding using a deterministic, testable retrieval strategy. Start with lexical/path-aware scoring and fixed budgets. Embeddings are explicitly not required for v1 and no vector database is introduced.

The result is a small context packet that future AI enrichment can read without changing deterministic findings.

## Contract

1. Input is only CG-016 `CorpusChunk` data plus deterministic analysis facts: changed paths, file statuses, deterministic findings and rule IDs.
2. Use deterministic lexical signals: exact path segment overlap, filename overlap, schema kind, heading text and token overlap from changed paths or finding evidence.
3. Enforce numeric budgets: maximum 12 chunks per report, maximum 4 chunks per changed file, maximum 24 KiB total selected text.
4. Return a stable ordered context packet containing selected chunk IDs, reasons and omitted counts.
5. Ties sort by score descending, then path, side, start range and SHA.
6. If no context matches, return an explicit empty context packet; do not invent summaries.
7. No embeddings, ANN index, vector database, external API, filesystem scan or model call.
8. Retrieval must be reproducible across Python runs; do not rely on set iteration order.

## Acceptance criteria

- A changed `openapi.yaml` ranks an API schema chunk above an unrelated ADR chunk.
- A dependency finding mentioning `pyproject.toml` ranks README installation guidance only when lexical/path evidence overlaps.
- Budgets are enforced exactly and omitted chunk counts are reported.
- Empty corpus returns an explicit empty packet and does not fail analysis.
- Evaluation fixtures declare expected chunk IDs and pass with 1.0 deterministic retrieval accuracy for the included examples.
- Retrieval results contain provenance references only to CG-016 chunks; no raw local files are read.

## Security and failure semantics

- Repository text remains untrusted. Retrieval may quote or pass it onward as data only.
- A high lexical score means relevance for review context, not proof that a claim is true.
- Oversized corpus must degrade by deterministic trimming with metadata, not by unbounded memory growth.
- Partial retrieval status must be visible to CG-020; silent missing context is not acceptable.

## Non-goals

- Semantic embeddings, rerankers, vector stores or LLM-based retrieval.
- Repository checkout access or shell commands.
- New deterministic risk rules.
- User-configurable ranking DSL.
