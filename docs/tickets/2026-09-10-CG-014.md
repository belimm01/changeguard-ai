# CG-014 — Add an authenticated bounded FastAPI analysis endpoint

Date: 2026-09-10
Status: Done
Depends on: CG-008, CG-009, CG-010, CG-011, CG-012, CG-013

## Outcome

ChangeGuard exposes a synchronous, authenticated FastAPI endpoint that accepts a bounded analysis request, invokes the existing injected analysis pipeline, and returns the versioned report without acting as a public webhook or policy enforcer.

## Design principles

- The HTTP layer is a boundary: authenticate, validate, limit, and delegate.
- Inject the application pipeline so endpoint tests can use fakes without network or GitHub credentials.
- Synchronous request/response is acceptable for v1 if strict time and size bounds are enforced; durable jobs come in CG-015 and workers later.

## Files

Create proposed:

- `src/changeguard/api/app.py` — FastAPI app factory and route wiring.
- `src/changeguard/api/auth.py` — shared-secret authentication dependency.
- `src/changeguard/api/models.py` — request/response DTOs if separate from report DTOs.
- `tests/unit/api/test_analysis_endpoint.py` — auth, validation, bounds, and injected-pipeline tests.
- `tests/integration/test_api_app.py` — optional ASGI smoke tests.

Modify existing:

- `pyproject.toml` and `uv.lock` — add `fastapi` and any required ASGI test dependency with bounded major ranges.
- `src/changeguard/config.py` — add API secret, request size, timeout, and pagination bound settings without logging secrets.
- `src/changeguard/reporting.py` or application composition root — expose the callable endpoint should inject.

## Request contract

Define an explicit request model containing only values needed now, for example repository owner/name, PR number, expected base/head SHAs, and optional analysis version. Do not present webhook payloads, GitHub App auth, or database-backed job APIs as existing.

## Acceptance criteria

- Requests without auth return 401; requests with a wrong secret return 403 or 401 consistently and never include the configured secret in logs or response bodies.
- Auth uses a configured secret supplied outside source code; tests inject it explicitly.
- Request validation rejects missing repository, invalid PR number, empty SHAs, oversized bodies, and unsupported origins with 4xx responses.
- The endpoint calls the injected existing pipeline once and returns the CG-008 versioned report shape.
- Pipeline partial results return HTTP 200 with `status="partial"`; advisory findings do not turn the request into a failure.
- Boundary failures such as GitHub rate limits or content truncation are represented in the report when the pipeline returns them.
- Unexpected internal exceptions return a bounded 500 response without tracebacks, tokens, patches, or raw repository content.
- The endpoint is not a GitHub webhook and does not verify webhook signatures yet; CG-023/CG-024 handle that.
- Tests use FastAPI's test client or ASGI client; no live GitHub calls.

## Non-goals

- No public webhook, GitHub App auth, Check Run publishing, database queue, background worker, or LLM orchestration.
- No auto-merge, blocking, approval, or repository-code execution.
- No Kubernetes deployment artifact yet.
