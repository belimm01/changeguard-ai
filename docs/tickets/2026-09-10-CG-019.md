# CG-019 — Validate AI citations and evidence deterministically

Date: 2026-09-10
Status: Planned
Depends on: CG-008, CG-010, CG-018

## Outcome

Validate every AI-generated advisory statement against deterministic evidence before it can appear as a supported claim. The validator checks citation membership, SHA provenance, ranges and quoted content. It rejects fabricated severities, invented evidence and any confirmed-sounding claim without an accepted source.

Source support permits display of a cited advisory statement; it does not prove the semantic claim is true.

## Contract

1. Input is structured output from CG-018 plus allowed sources from CG-010 evidence and CG-017 context packets.
2. Every AI claim must cite at least one source ID that exists in the allowed source set.
3. Each citation must match path, side, blob SHA and range. A path-only citation is invalid.
4. If the model quotes content, the quoted text must be contained in the cited source range after deterministic whitespace normalization.
5. AI cannot create or upgrade deterministic severity. If it supplies severity, map it to `advisory_severity` and reject values outside the allowed enum.
6. AI cannot remove, downgrade or contradict deterministic findings. Deterministic findings remain authoritative in the report.
7. Statements using confirmed language such as `will break`, `is vulnerable` or `definitely` require source-backed deterministic evidence; otherwise mark unsupported or reject according to the output shape.
8. Validation returns accepted advisory items, rejected items with reasons and aggregate counts.
9. No model call, repository read, network call or semantic entailment engine is part of this validator.

## Acceptance criteria

- A citation to an unknown source ID is rejected.
- A citation with the right path but wrong SHA is rejected.
- A quote not present in the cited range is rejected.
- A model-created critical severity for a deterministic warning is rejected or downgraded to an explicitly advisory field without changing the deterministic finding.
- A claim with no citation is rejected from supported output.
- Validation result reports accepted and rejected counts exactly.
- Supported AI output can only reference source IDs from CG-010/CG-017 input packets.

## Security and failure semantics

- Treat model output as hostile JSON. Validate lengths, enum values and citation counts before using strings in reports.
- Do not rely on the model's own explanation that a citation is valid.
- Failed validation produces explicit partial AI status; it must not fail deterministic analysis.
- Source membership and quote matching are mechanical checks. They do not prove the AI interpreted the source correctly.

## Non-goals

- Natural-language entailment, fact checking or vulnerability proof.
- Letting AI assign final merge/block decisions.
- Rewriting deterministic findings.
- Provider-specific response parsing beyond the structured schema from CG-018.

## Definition of done

- AI advisory output is mechanically citation-validated before display as supported.
- Fabricated source IDs, SHAs, ranges, quotes and severities are rejected by tests.
- Validation failures are visible as partial AI status and do not affect deterministic findings.
