# CG-009 — Add a bounded async GitHub PR metadata and files reader

Date: 2026-09-10
Status: Planned
Depends on: CG-008

## Outcome

ChangeGuard can read pull-request metadata and changed-file pages from a configured trusted GitHub origin with injected credentials, bounded pagination, retry/cancel handling, and explicit incomplete coverage when limits or rate limits are hit.

## Design principles

- Network adapters sit outside the domain and translate remote payloads into trusted internal inputs.
- Async clients need explicit timeouts, cancellation behavior, and pagination caps.
- Credentials are injected configuration, never literals in source, tests, logs, or snapshots.

## Files

Create proposed:

- `src/changeguard/adapters/github_client.py` — async GitHub API reader using `httpx`.
- `src/changeguard/config.py` — minimal typed settings for GitHub base URL, token source, timeouts, and caps if no config module exists yet.
- `tests/unit/adapters/test_github_client.py` — mocked transport tests for pagination, auth, retries, and limits.

Modify existing:

- `pyproject.toml` and `uv.lock` — add `httpx` with a bounded major-version range.
- `src/changeguard/adapters/github.py` — reuse parsing helpers if useful; do not mix raw HTTP with domain validation.
- `src/changeguard/domain/reports.py` or coverage module from CG-008 — represent incomplete remote reads.

## Acceptance criteria

- The client accepts only a configured trusted origin such as `https://api.github.com`; repository URLs from PR input do not override it.
- Authorization is supplied by injected settings or function parameters and never logged; tests assert the token is present in the request header and absent from exceptions/log text.
- PR metadata includes repository owner/name, PR number, base SHA, head SHA, title/body when available, and API URL or equivalent evidence source.
- Changed files are fetched across pages up to a configured maximum page count and/or file count.
- If pagination exceeds the cap, the result is marked incomplete with a coverage reason; it is not treated as safe or complete.
- HTTP 429/403 rate-limit responses, selected 5xx responses, timeout, and network errors use bounded retry/backoff behavior or return explicit incomplete/failure status as designed.
- `asyncio.CancelledError` is not swallowed.
- The adapter returns typed internal data; it does not run rules or serialize the final report.
- Tests use `httpx.MockTransport` or equivalent in-process mocking; no live GitHub calls.

## Non-goals

- No GitHub App installation-token flow; credential injection is temporary until CG-023.
- No webhook endpoint, database queue, repository checkout, or file-content download.
- No GraphQL unless a concrete tested need appears.
