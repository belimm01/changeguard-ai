# CG-003 — Validate and translate GitHub changed-file payloads

Date: 2026-09-06
Status: Done

## Outcome

ChangeGuard validates an untrusted GitHub changed-files payload and translates
it into the immutable `ChangeSet` domain model used by deterministic rules.

## Design principles

- This is the adapter at the external trust boundary. It comes before any HTTP
  or GitHub API integration.
- `GitHubChangedFile(BaseModel)` validates the untrusted payload at runtime;
  Python type hints alone do not.
- Pydantic v2 stays in the adapter. The internal `ChangedFile` remains a plain
  frozen dataclass, so rules are not coupled to a validation framework.
- No GitHub SDK, FastAPI, network or filesystem access.

## Files

- `src/changeguard/adapters/github.py` — `parse_github_changed_files`
- `tests/unit/adapters/test_github.py`

## Input contract

`parse_github_changed_files(payload)` receives an untrusted object. A valid
payload is a list of GitHub file records containing:

- `filename: str`
- `status`: one of `added`, `modified`, `deleted` or `renamed`
- `additions: int >= 0`
- `deletions: int >= 0`
- optional `patch: str | None`

Unknown GitHub fields are ignored, and the input is never mutated.

## Output contract

Return `ChangeSet(files=...)` where:

- each record becomes one `ChangedFile`, preserving order;
- `filename` maps to `path`, and `status` maps to `ChangeType`;
- a missing `patch` becomes `None`;
- an empty list becomes `ChangeSet(files=())`.

Malformed outer data, missing fields, unknown statuses and negative counters
raise `pydantic.ValidationError`, which the adapter does not catch; the API layer
decides how to represent it. Unsafe paths are still rejected by the domain model
with `ValueError`, and that validation is not duplicated. The adapter never
returns Pydantic models.

## Acceptance criteria

- Valid, empty and extra-field payloads translate correctly.
- Every invalid-input category is tested.
- All four statuses and a missing patch are covered.
- Domain path validation remains active.
- Provider order and input data are preserved.
