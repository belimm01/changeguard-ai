# CG-008 — Introduce a versioned analysis report, evidence, and coverage model

Date: 2026-09-10
Status: Done
Depends on: CG-007

## Outcome

ChangeGuard returns a versioned report envelope that snapshots base/head SHAs, findings, evidence, coverage, and partial-analysis status while preserving the CG-005 finding serializer for existing callers.

## Design principles

- A report envelope separates stable public output from internal domain objects.
- Evidence should be structured enough for tests and citations, not only prose.
- Missing input means `partial`, `unsupported`, or `incomplete`; it must not be interpreted as safe.

## Files

Create proposed:

- `src/changeguard/domain/reports.py` — immutable report, evidence, coverage, and status domain models.
- `src/changeguard/dto/reports.py` — Pydantic response DTOs with an explicit schema version.
- `src/changeguard/reporting.py` — new report serializer/composer that uses existing findings.
- `tests/unit/test_reporting.py` — report serialization and compatibility tests.

Modify existing:

- `src/changeguard/serialization.py` — keep `serialize_findings()` compatible; do not replace its current shape.
- `src/changeguard/application/analysis.py` — only if a thin report composition seam belongs there.

## Acceptance criteria

- Existing `serialize_findings(tuple[RiskFinding, ...])` output remains byte-for-byte compatible with CG-005 tests.
- A new explicit report serializer emits a dictionary with `schema_version`, `analysis_version`, `repository`, `pull_request`, `base_sha`, `head_sha`, `status`, `findings`, `evidence`, and `coverage` or deliberately equivalent documented names.
- `base_sha` and `head_sha` are required for a complete report and serialized exactly as supplied; do not normalize malformed values silently.
- Missing files, truncated GitHub pagination, unsupported formats, and content-fetch failures produce `status="partial"` or scoped coverage entries, not `status="complete"`.
- Coverage records include rule id, target or path pattern, supported/unsupported/partial state, and a short reason.
- Evidence records can point to a file path and optional line range without requiring repository checkout.
- JSON output ordering is deterministic enough for snapshot tests.
- No LLM recommendation fields are required yet; leave a documented future extension point rather than fake AI output.

## Non-goals

- No GitHub network reader, content fetcher, FastAPI, database, or LLM adapter.
- No OpenAPI/Avro/Kubernetes rule implementation yet.
- No breaking change to the CG-006 CLI unless explicitly done as a compatible opt-in.
