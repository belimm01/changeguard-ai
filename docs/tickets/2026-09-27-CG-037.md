# CG-037 — Evaluate MCP tool use with DeepEval

Date: 2026-09-27
Status: Planned
Depends on: CG-021, CG-036

## Outcome

ChangeGuard can measure whether an MCP client uses the read-only CG-036 server correctly: it picks the right tool, passes valid arguments, answers from the returned report/evidence only, reports partial coverage honestly, and ignores instructions embedded in untrusted report text. Results are reproducible offline by default; LLM-judged DeepEval metrics run only in an explicit, cost-bounded live mode.

## Practical use

CG-036 proves the server returns correct data. It does not prove that an assistant asks for the right data or represents it faithfully. This ticket adds that evidence: a small golden set of developer questions ("why is the report for owner/repo PR 123 partial?", "show evidence for finding X") with expected tool calls, scored by DeepEval's MCP metrics, so MCP changes and tool-description edits can be regression-checked instead of judged by eye.

## Design principles

- Two evaluation layers:
  - Offline, deterministic (default): recorded, redacted MCP interaction transcripts are replayed and checked exactly — tool name, argument values, no forbidden/extra calls, coverage status present in the answer. No network, credentials or model cost. Extends the CG-021 harness.
  - Live, opt-in: a real MCP client session against a disposable CG-036 server produces fresh transcripts, scored with DeepEval `LLMTestCase(mcp_servers=..., mcp_tools_called=...)` and `MCPUseMetric` (single turn) / `MultiTurnMCPUseMetric` (multi turn) using an LLM judge.
- LLM-as-judge is itself an unverified model opinion: record judge provider, model, threshold and reason; never report a judge score as ground truth or let it replace the deterministic checks.
- Report text, findings and citations stay untrusted data inside the eval too. Injection goldens must prove the client does not follow instructions found in tool results.

Modify existing:

## Contract

1. Default `uv run pytest -q` runs only the offline MCP replay and needs no `deepeval` install, network, API key or model cost.
2. Live mode requires all of: `uv sync --group eval`, the pytest marker selected, an explicit enable flag, an explicitly configured judge (for example DeepEval `AnthropicModel`) and a per-run case/cost cap. Missing any of them skips with a clear reason; it never silently falls back to a default paid provider.
3. `DEEPEVAL_TELEMETRY_OPT_OUT=YES` is set for every eval run; no results are uploaded to Confident AI or any hosted dashboard.
4. Goldens cover at least: `get_report`, `list_findings`, `get_evidence`, `explain_coverage`, an out-of-allow-list repository (expected: denied, no fabricated answer), a partial/unsupported report (expected: partial status stated), and a prompt-injection report text (expected: no extra tool calls, instruction not followed).
5. Offline thresholds are exact: tool-name match `== 1.0`, required-argument match `== 1.0`, forbidden-call count `== 0`, injection resistance `== 1.0`.
6. Live thresholds are declared per metric in the goldens/manifest (starting point `MCPUseMetric >= 0.7`) and each run records per-case score, judge reason, judge model and token/cost usage.
7. Transcripts contain no tokens, local paths, environment values or unredacted private repository content.

## Acceptance criteria

- Offline replay tests fail first on a deliberately wrong recorded tool call, then pass on the correct golden transcripts.
- Offline MCP evaluation runs in the normal gates without the `eval` group installed.
- `deepeval` appears only in the `eval` dependency group; `uv lock --check` passes.
- One documented live run against a disposable CG-036 server + PostgreSQL scores all goldens with DeepEval, with judge model, thresholds, pass/fail per case and total cost recorded and secrets redacted.
- Injection and denied-repository goldens pass in both offline and live modes.
- Judge scores are reported separately from deterministic results and never used to mark a failed deterministic check as passing.

## Non-goals

- No DeepEval in runtime code, the MCP server, the worker or CI by default (CG-029 may add the offline replay only).
- No Confident AI account, hosted dashboards, synthetic dataset generation or red-teaming framework (DeepTeam).
- No evaluation of the core analysis quality; CG-021 owns that.
- No agent framework, autonomous tool use beyond the CG-036 read-only tools, or write-capable tools added to make evaluation easier.
