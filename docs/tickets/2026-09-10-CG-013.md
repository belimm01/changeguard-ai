# CG-013 — Add a scoped Kubernetes risky manifest change rule

Date: 2026-09-10
Status: Done
Depends on: CG-010

## Outcome

ChangeGuard safely parses Kubernetes YAML manifests from base/head content and reports a small set of risky workload and service changes with evidence and unsupported coverage.

## Design principles

- Kubernetes manifests are declarative desired state, but unsafe changes still need review.
- YAML parsing must be safe and bounded; repository YAML is untrusted input.
- Multi-document manifests require deterministic object identity and ordering.

## Files

Create proposed:

- `src/changeguard/rules/kubernetes.py` — scoped risky manifest change rule.
- `src/changeguard/parsing/kubernetes.py` — safe multi-document YAML parsing helpers if useful.
- `tests/unit/rules/test_kubernetes.py` — rule tests for supported risky changes and partial coverage.
- `tests/fixtures/kubernetes/` — small base/head manifests.

Modify existing:

- `src/changeguard/domain/content.py` and `src/changeguard/domain/reports.py` — reuse evidence and coverage types.

## Supported v1 subset

For Kubernetes YAML/JSON manifests:

- Detect `Deployment` or `StatefulSet` container image tag changes, especially to `latest`.
- Detect container resource requests/limits removal or significant reduction if a simple threshold is implemented.
- Detect adding privileged containers, host network, host PID, host IPC, or privilege escalation.
- Detect `Service` type changes to `LoadBalancer` or `NodePort`.
- Detect removal or broadening of selected labels in workload selectors if implemented narrowly.
- Mark CRDs, Helm templates, Kustomize overlays, Jsonnet, and unrendered templates as unsupported unless deliberately handled.

## Acceptance criteria

- YAML parsing uses safe loading and enforces document count and byte limits.
- Invalid YAML, templates containing unresolved directives, binary content, and oversized manifests produce partial/unsupported coverage.
- The rule deterministically identifies objects by `apiVersion`, `kind`, `metadata.namespace`, and `metadata.name`.
- Image tag change to `latest`, service exposure to `LoadBalancer`, and privileged security-context change each produce advisory findings with path and line/source evidence when available.
- Existing unsupported kinds are represented as coverage, not ignored as safe.
- The rule does not run `kubectl`, Helm, Kustomize, Jsonnet, admission controllers, or repository scripts.
- Findings are advisory and compatible with the report model from CG-008.

## Non-goals

- No full Kubernetes policy engine.
- No cluster access, live API discovery, admission simulation, or Helm rendering.
- No organizational policy defaults beyond the scoped checks above.
