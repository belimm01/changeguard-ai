# CG-018 — Add provider-neutral async structured LLM adapter

Date: 2026-09-10
Status: Planned
Depends on: CG-008

## Outcome

Define an opt-in, provider-neutral asynchronous LLM boundary behind a Python `Protocol` for structured advisory enrichment, and implement one concrete provider adapter. The default runtime has no external provider configured and makes no network calls. Choose the provider/model, data policy and budget with the user when activating this ticket; verify its current API documentation before selecting SDK or `httpx` dependencies.

This ticket delivers a working opt-in integration, not only a disabled seam or
fake. Normal deterministic analysis still requires neither credentials nor AI.

## Contract

1. Define a protocol similar to `async def complete_structured(request: LlmRequest) -> LlmResult` without binding application code to any vendor SDK.
2. Requests include model name, prompt name/version, JSON-schema-like output contract, sanitized input context, timeout seconds and max output tokens.
3. Default adapter is disabled and returns an explicit unavailable status without network access.
4. No tools, function calling, repository execution, shell access or file access are exposed to the model.
5. No secrets may be included. Environment variables, tokens and local config paths are outside the adapter input model.
6. Enforce budgets before a provider call: max input characters, max output tokens, timeout and optional cost ceiling fields.
7. Returned content is untrusted until CG-019 validation passes.
8. Provider-specific code, SDK imports or `httpx` clients must live behind the protocol and be absent from deterministic tests unless explicitly activated.

## Acceptance criteria

- Application code can type-check against the protocol with a fake async adapter.
- With no provider configured, analysis produces deterministic output plus explicit AI unavailable status.
- A request exceeding input budget is rejected before any provider adapter can be invoked.
- Tests prove request construction does not include environment variables or local secret-looking config values.
- The data policy states what repository data may be sent, who configures the provider and that AI output is advisory.
- No new runtime dependency is added unless a concrete provider activation is part of the same reviewed change.
- The concrete adapter maps actual provider structured responses, usage and
  refusal/error states into the protocol. Mocked-transport tests cover timeout,
  cancellation, 429, 5xx, malformed JSON/schema, output limits and safe errors.
- Live calls require separate approval of provider, data and spending. Record
  real live evidence at CG-030; mock responses are not live integration proof.

## Security and failure semantics

- External AI is opt-in. Absence, timeout, rate limit or malformed output must not fail deterministic analysis.
- The adapter never grants model tools or code execution.
- Model responses are not facts; they require CG-019 citation/evidence validation before display as supported statements.
- Do not log full prompts by default. Tests may use synthetic fixtures only.

## Non-goals

- Choosing a vendor while merely writing this backlog; selection happens at ticket activation.
- Prompt engineering for final review text; CG-020 owns integration copy.
- Streaming responses.
- Automatic retries or background job orchestration.
