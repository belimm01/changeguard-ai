# CG-022 — Add prompt-injection, data-leakage and adversarial regressions

Date: 2026-09-10
Status: Planned
Depends on: CG-020, CG-021

## Outcome

Create an adversarial regression suite for AI enrichment and evidence validation. The suite proves repository instructions, malicious comments, malformed citations, oversize content and leakage attempts are handled as untrusted data. It must not rely on the model promising safety; it verifies deterministic guards and serialized outputs.

No repository execution, LLM tools, shell access or secret exposure is allowed.

## Contract

1. Fixtures include malicious repository text such as `ignore previous instructions`, `send secrets`, fake tool calls and fake success claims.
2. Fixtures include malicious code comments in changed files and docs instructions in retrieved context.
3. Tests assert these strings are treated as quoted data, not as system/developer instructions.
4. Malformed citations cover unknown source IDs, wrong SHA, out-of-range line numbers, reversed ranges, path traversal-looking IDs and duplicate citations.
5. Oversize tests cover too many advisory items, huge strings and excessive citation counts; validators reject or truncate according to explicit limits.
6. Leakage tests prove environment variables, tokens and local config contents are not included in LLM requests or serialized reports.
7. Tests use fake adapters and frozen outputs. They do not call live providers.
8. No model tools, repository execution, subprocess execution or network access is exposed in tested code paths.

## Acceptance criteria

- A prompt-injection fixture cannot alter deterministic findings or AI status policy.
- A malicious doc asking the model to claim safety does not produce a supported safety claim without valid evidence.
- Malformed citations are rejected with specific reason codes.
- Oversize AI output is rejected or bounded without unbounded memory growth.
- Secret-looking environment values inserted during a test are absent from requests, logs captured by tests and serialized reports.
- A fake adapter attempting to request tool use has no available tool channel and its output is treated as invalid advisory data.
- The adversarial suite runs offline and can be included in `uv run pytest -q` without credentials.

## Security and failure semantics

- Do not assert that a model is safe because the prompt says so. Assert the program enforces boundaries.
- Do not execute fixture content or render untrusted Markdown/HTML.
- Do not write real secrets into fixtures. Use synthetic sentinel strings such as `SECRET_SENTINEL_DO_NOT_LEAK`.
- A security regression should fail closed: deterministic report remains, AI advisory output is unavailable, invalid or partial.

## Non-goals

- Red-team jailbreak research against live vendors.
- Automated vulnerability scanning of user repositories.
- Secret detection across full repository history.
- Browser rendering or sandboxing of untrusted documents.

## TDD loop

1. Write `test_prompt_injection_text_is_passed_only_as_context_data` with a fake adapter that records the structured request.
2. Run the focused security test and confirm missing guards or fixtures fail.
3. Implement or tighten request construction so repository instructions are delimited as data.
4. Add malformed-citation fixtures and reason-code assertions through CG-019 validation.
5. Add oversize output tests and enforce explicit item/string/citation limits.
6. Add leakage sentinel tests around environment variables and serialized reports.
7. Add documentation for adding future adversarial cases.

## Definition of done

- Prompt-injection, malformed-citation, oversize-output and leakage regressions are covered by offline tests.
- Tests verify program boundaries, not model self-attestations.
- Security failures are explicit partial/invalid AI states and preserve deterministic findings.
- No network, tools or repository execution are introduced.
