# CG-002 — Detect Python dependency changes

Date: 2026-09-06
Status: Done

## Outcome

ChangeGuard produces one deterministic, evidence-backed advisory finding when a
pull request changes Python dependency definitions or lock files.

## Design principles

- This is the first analysis rule, and it involves no LLM. Deterministic
  findings are the verified evidence that later AI explanations must cite,
  rather than asking a model to infer facts from a raw diff.
- A rule is a pure function: the same `ChangeSet` always yields the same
  findings, with no side effects, so it needs no service object or dependency
  injection.

## Files

- `src/changeguard/rules/python_dependencies.py`
- `src/changeguard/domain/findings.py` — `RiskFinding`, `RiskLevel`
- `tests/unit/rules/test_python_dependencies.py`

## Contract

Recognize these exact file names at any repository depth: `pyproject.toml`,
`uv.lock`, `poetry.lock`, `Pipfile`, `Pipfile.lock`, `requirements.txt` and
`requirements-dev.txt`.

- The final path component must match exactly. `services/api/pyproject.toml`
  matches; `pyproject.toml.backup` does not.
- Every `ChangeType` is in scope, including deletions. Patch contents are not
  inspected.
- No match returns `()`.
- One or more matches return exactly one `RiskFinding`:
  - `rule_id="python-dependency-change"`
  - `level=RiskLevel.MEDIUM`
  - `summary="Python dependency files changed; review dependency and lockfile consistency."`
  - `evidence_paths`: the matching paths, sorted and unique

## Acceptance criteria

Tests cover:

- no match;
- a single manifest;
- every supported file name;
- multiple matches aggregated into one finding with sorted, unique evidence;
- similar names that must not match;
- nested manifests;
- every change type;
- patch content neither creating nor suppressing a finding.

Output order is deterministic, and results are tuples, not mutable lists.

## Constraints

No HTTP, GitHub SDK, database, LLM or agent framework. Inputs are never
mutated, and the finding remains advisory.
