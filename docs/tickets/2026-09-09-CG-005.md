# CG-005 — Serialize deterministic analysis findings

Date: 2026-09-09
Status: Done

Implementation note (2026-09-10): the current implementation uses an explicit
Pydantic v2 response DTO at the serialization boundary, reusing the existing
dependency. Domain dataclasses remain framework-independent. This supersedes
the original standard-library-only serialization constraint.

## Outcome

ChangeGuard converts the immutable findings returned by `run_analysis` into a
stable, JSON-compatible response object for future HTTP, CLI, and webhook
boundaries. Serialization must not change finding order or discard evidence.

## Why this is next

CG-004 now orchestrates deterministic rules, but its tuple result is an
internal Python representation. Before adding an API or GitHub integration, we
need one provider-neutral output contract that can be tested without network or
framework dependencies.

## Contract

Add a function with this contract:

```python
def serialize_findings(
    findings: tuple[RiskFinding, ...],
) -> tuple[dict[str, object], ...]: ...
```

For every finding, produce a dictionary containing exactly:

- `rule_id: str`
- `level: str` using the enum value (`"low"`, `"medium"`, or `"high"`)
- `summary: str`
- `evidence_paths: list[str]`, documented by the tests

The function must:

- preserve finding order;
- preserve evidence path order;
- return an empty tuple for empty input;
- return a tuple, not a list, at the outer boundary;
- not mutate findings or their evidence;
- not sort, deduplicate, enrich, or infer fields;
- not include dataclass implementation details.

If the implementation chooses lists for `evidence_paths`, the result must be
JSON-serializable using the Python standard library without a custom encoder.

## Tests

Implement tests for:

1. empty findings;
2. one finding and every serialized field;
3. multiple findings with preserved order;
4. multiple evidence paths with preserved order;
5. all `RiskLevel` values;
6. JSON serialization with `json.dumps`;
7. input immutability by comparing the original findings after serialization.

## Constraints

- Map fields explicitly to `FindingDto`, then use `model_dump(mode="json")`.
- No FastAPI, GitHub SDK, new dependencies, or network calls.
- Keep `RiskFinding` and `RiskLevel` unchanged unless a concrete defect is
  found.
- Use explicit field construction rather than `dataclasses.asdict` so the
  external contract does not accidentally expose future internal fields.
