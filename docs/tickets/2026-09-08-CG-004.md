# CG-004 — Orchestrate deterministic analysis rules

Date: 2026-09-08
Status: Done

## Outcome

ChangeGuard executes an ordered collection of analysis rules and returns one
immutable, ordered tuple containing all findings.

## Design principles

- Rules are composed before any HTTP endpoint or LLM layer is added.
- `AnalysisRule` is a callable type, so any function with the declared
  signature can be passed to `run_analysis`. Python functions are first-class
  values, so this is dependency injection without a container.
- Rules are supplied explicitly as a tuple. There is no global mutable
  registry.
- Each rule owns its evidence ordering and deduplication. The orchestrator
  neither sorts nor deduplicates.

## Files

- `src/changeguard/application/analysis.py` — `AnalysisRule`, `run_analysis`
- `tests/unit/test_analysis.py`

## Contract

`run_analysis(change_set, rules)`:

- executes every rule exactly once, in the order supplied;
- passes the same immutable `ChangeSet` instance to every rule;
- flattens the rule results into one tuple, preserving each rule's finding
  order;
- returns `()` when `rules` is empty or every rule returns `()`;
- propagates a rule exception immediately, without running later rules.

It adds no concurrency, retries, exception wrapping, sorting or deduplication.

## Acceptance criteria

- Tests cover:
  - no rules;
  - the Python dependency rule run through the orchestrator;
  - two fake rules, checking rule and finding order;
  - each rule called once with the same `ChangeSet`;
  - empty results not producing nested tuples;
  - exception propagation stopping later rules.
- The return type is a tuple, not a list or generator.
