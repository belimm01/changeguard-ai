# CG-035 — LLM guardrails: redaction and prompt-injection defense

Date: 2026-09-13
Status: Planned
Depends on: CG-018, CG-019, CG-022

## Outcome

Add an input/output guardrail layer around the LLM boundary: redact secrets and
PII from context before it is sent, apply prompt-injection heuristics to retrieved
repository context, and validate model output against a policy before it is
displayed. Guardrails complement, not replace, CG-019 citation validation and
CG-022 adversarial regressions.

This is a post-v1 job-skill extension (LLM safety/guardrails), not a v1 release
requirement. Deterministic analysis is unaffected.

## Contract

1. Input redaction removes secret-shaped and PII-shaped tokens before any send;
   redaction is verified by tests, not just declared.
2. Injection heuristics flag retrieved context containing instruction-override
   patterns (e.g. "ignore previous instructions") and mark it as untrusted data,
   never as instructions.
3. Output-policy checks reject content that leaks system prompts, fabricates
   citations (defers to CG-019) or violates advisory-only constraints.
4. Guardrails are pure and deterministic; no network and no model call.
5. A rejected output yields an explicit safe status, never silent passthrough.
6. Negative cases: safe content resembling risky patterns must not be over-blocked.

## Acceptance criteria

- Secret/PII-shaped tokens are absent from the constructed provider input.
- Known injection strings in retrieved context are flagged and quarantined.
- Output that leaks the system prompt is rejected with a safe status.
- Safe-lookalike inputs are not falsely redacted or blocked.

## Non-goals

- A trained classifier or external moderation API; heuristic/deterministic only.
- Replacing CG-019 citation validation or CG-022 leakage regressions.
- Guaranteeing complete injection immunity; this is defense-in-depth.

## TDD loop

1. Write a failing test asserting a secret-shaped token is redacted from input.
2. Run it and confirm it fails for the expected reason.
3. Add redaction; add injection-heuristic detection tests.
4. Add output-policy rejection tests and safe-lookalike negatives.
