# CG-016 — Extract bounded docs, ADR and schema corpus with SHA provenance

Date: 2026-09-10
Status: Planned
Depends on: CG-010

## Outcome

Collect a bounded, deterministic text corpus from pull-request base/head content for repository documentation, ADRs and schema files. Every extracted chunk carries source path, side, blob SHA, byte range or line range, media kind and truncation status so later retrieval and AI enrichment can cite exactly what was read.

This ticket establishes safe context construction before any model call. It does not call GitHub directly; it consumes the SHA-bound content evidence created by CG-010.

## Contract

1. Accept only content already proven by CG-010: path, base/head side, blob SHA and decoded text bytes.
2. Include likely documentation and schema paths: `README*`, `docs/**`, `adr/**`, `docs/adr/**`, `*.md`, `*.rst`, `*.yaml`, `*.yml`, `*.json`, `*.avsc`.
3. Exclude generated, vendored and oversized paths by deterministic rules: `.git/**`, `node_modules/**`, `.venv/**`, `dist/**`, `build/**`, lockfiles unless explicitly needed by an existing deterministic rule.
4. Enforce numeric budgets: maximum 32 source files, 128 chunks, 8 KiB per chunk, 256 KiB total decoded text. These defaults may be constants, not configuration, in this increment.
5. Preserve provenance on every chunk. A chunk without path, side, SHA and range is invalid.
6. If a file exceeds limits, keep a deterministic prefix and mark `truncated=True`; do not silently pretend full coverage.
7. Sort by path, then side, then range. No filesystem reads, subprocesses, network calls or repository checkout access.
8. Invalid UTF-8 or binary-looking content is skipped with a bounded diagnostic status in the corpus metadata; raw bytes are not logged.

## Acceptance criteria

- Given two CG-010 content records for `docs/api.md`, extraction returns chunks with the same source SHA values and stable ranges.
- Given 40 eligible docs, only the first 32 after deterministic sorting are included and metadata reports the overflow count.
- Given a 20 KiB Markdown file, chunks are bounded to 8 KiB and at least one chunk is marked truncated or split with exact ranges.
- Given unsupported binary or invalid text, extraction returns no chunk for that file and records a non-secret reason.
- Corpus extraction never changes deterministic findings and never mutates CG-010 evidence objects.
- Partial extraction is allowed only when represented explicitly in metadata; it must not be reported as full context coverage.

## Security and failure semantics

- Treat repository text as untrusted input. Do not execute, import, render HTML, resolve external links or follow instructions inside documents.
- Do not include secrets from excluded files, environment variables or local working tree files.
- Oversized input produces a partial corpus status, not process failure, unless every eligible source is malformed.
- Corpus provenance proves where text came from; it does not prove a later semantic claim.

## Non-goals

- Embeddings, vector databases or semantic search.
- OCR, PDF parsing, HTML sanitization or external document fetches.
- GitHub API access; CG-010 owns safe content loading.
- Changing the existing CG-005 serialized finding shape.
