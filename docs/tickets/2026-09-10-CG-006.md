of evidence-backed findings on stdout. This is the first executable vertical
slice: GitHub-shaped JSON → validated adapter → domain → rules → serializer.
The result is advisory; finding a risk does not mean the command failed.

## Design principles

- A composition root wires existing functions together at the outer boundary.
- `argparse` handles CLI syntax; application rules must not depend on it.
- stdout is the machine-readable result; stderr is for bounded diagnostics.
- `SystemExit` belongs in the module entry point, not in the reusable runner.

## Contract

Expose a runner in `changeguard.cli`:

```python
def main(
    argv: Sequence[str] | None = None,
    *,
    stdin: TextIO | None = None,
    stdout: TextIO | None = None,
    stderr: TextIO | None = None,
) -> int: ...
```

Use `collections.abc.Sequence` and `typing.TextIO`. Resolve `None` streams at
call time. Handle CLI options with the standard-library `argparse` module.
Normal processing returns an exit code; argparse may use its standard
`SystemExit` behavior for help and invalid arguments.

1. No positional arguments or input-file flags in this increment: read one
   UTF-8 JSON document from stdin. Shell redirection supplies files.
2. Validate the decoded object with the existing GitHub adapter, then run an
   explicitly supplied tuple containing the existing dependency rule once.
3. Serialize through the existing serializer. Write exactly one JSON array plus
   a trailing newline to stdout. Do not print banners or diagnostic logs there.
4. Return 0 on successful analysis, including findings and an empty result.
5. Malformed JSON, invalid GitHub payloads and input decoding/read failures
   return 2, leave stdout empty, and emit one short diagnostic line on stderr.
   Do not echo the raw payload, patches, Pydantic exception dump or traceback.
6. Unexpected programming/rule failures must propagate; do not convert every
   exception into an input error. Catch only anticipated boundary exceptions.
7. `--help` exits 0 with usage; unknown arguments exit 2 before reading stdin.
8. Preserve existing finding/evidence ordering. No network or repository reads.
9. The entry point delegates to the runner and passes its status to `SystemExit`.

## Constraints and non-goals

- Standard library plus the already-installed Pydantic dependency only.
- No FastAPI, GitHub credentials/API, webhook server, LLM or agent framework.
- No new rules, global mutable registry, retry or catch-all exception wrapper.
- This is a local tool for a supplied JSON document, not a hardened public
  ingestion service. Resource limits and service authentication are separate work.
